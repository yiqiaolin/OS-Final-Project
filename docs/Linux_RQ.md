## 2. 研究問題與具體分析規劃（Research Questions & Analysis Ideas）

### RQ1｜Linux 系統日誌中，哪些系統活動最頻繁？它們的活動模式如何隨時間改變？

**研究項目：**
- **程序與事件分布：** 統計 Kernel、SSH、FTP 等主要程序及服務的日誌數量與比例，辨識最常見的系統活動。
- **事件模板分析：** 將重複訊息標準化，找出最常出現的事件模式，例如 OOM 程序終止、身分驗證失敗等。
- **時間變化分析：** 比較不同事件類型在各小時、各日期的發生頻率，觀察活動高峰與分布差異。

**預期成果：**
- 主要程序與事件類型的頻率排名及比例圖。
- 不同系統活動的時間序列圖。
- 找出資料集中最主要的系統活動，並解釋其對應的作業系統行為。

### RQ2｜潛在異常事件是否呈現時間集中或重複發生的特徵？

**研究項目：**
- **SSH 驗證失敗：** 分析驗證失敗事件是否集中於特定時間，以及是否存在短時間內反覆失敗的現象。
- **OOM 記憶體不足事件：** 分析程序終止紀錄的時間分布、受影響程序，以及是否存在連續發生的情況。
- **突發事件偵測：** 將日誌依分鐘分組，利用事件數量門檻與統計方法識別高密度時間窗，並檢查相關原始日誌。

**預期成果：**
- SSH 與 OOM 事件的時間分布及突發事件圖。
- 高密度事件時間窗的統計與代表性案例。
- 比較兩類事件的集中程度，探討不同作業系統事件的異常特徵。

### RQ3｜不同的規則式偵測方法，會如何影響潛在異常事件的辨識結果？

**研究項目：**
- **關鍵字式偵測：** 利用 `error`、`failed`、`failure` 等關鍵字尋找可能的異常事件。
- **作業系統語意規則：** 根據 OOM、驗證失敗、程序終止等具體事件訊息建立分類與偵測規則。
- **時間突發偵測：** 根據短時間內的事件密度識別異常候選時間窗。
- **方法比較：** 比較三種方法的命中數量、共同與獨有結果，並透過原始日誌案例分析可能的漏判與誤判。

**預期成果：**
- 三種異常偵測方法的結果比較表與圖表。
- 找出不同方法各自容易辨識或忽略的事件類型。
- 分析單純使用關鍵字或事件頻率的限制，探討結合作業系統知識進行日誌分析的價值。
